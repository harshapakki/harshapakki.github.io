CASE A · LEGACY → API → AI

        
Opening a decades-old ERP so quotes take a day, not three

        

          
Problem
Prices, stock and routings lived in an AS/400 behind green screens. Estimators re-keyed them into a shared spreadsheet, one quote at a time.

          
Built
A FastAPI data service over DB2 for i that serves live pricing, stock, catalogue and work-order routes as JSON. On top of it, a quoting platform with recursive cost roll-ups, single sign-on, and narrow agent tools so AI can answer from the same source.

          
Result
The ERP was never modified, and every new app or agent now starts from the same API.
            
2-3 days → 1 day per quote

            
≈ 40% more estimates

CASE B · APPLIED AI · COST

        
Digitising 1,800 engineering drawings for the price of a team lunch

        

          
Problem
Scanned drawings across 97 part families had to become structured, catalogue-valid data. By hand: about a month and $3-5K. With the best model on every page: accurate, and too expensive to repeat.

          
Built
A four-step escalation ladder. Cheap and exact first, one vision read next, a second read only on evidence, people last. Confidence comes from physical cross-checks (OCR agreement, geometry, mass against printed weight), never from the model's opinion of itself.

          
Result
Extraction became priceable per drawing instead of per project.
            
3 days · about $150 total

            
90% on adjudicated core fields

        

        
Python · vision models · OCR · local models via Ollama · golden-set evals

CASE C · SOFTWARE THAT MOVES METAL

        
Closing the loop between a gauge and a CNC machine

        

          
Problem
Operators measured parts, then typed tool-offset corrections into the controller by hand. Drift was caught late, and scrap followed.

          
Built
A C# controller that reads Keyence gauges and writes corrections to Siemens 828D tool-offset registers. A deadband ignores in-spec noise and a per-step clamp stops one bad reading from driving the tool.

          
Result
Corrections happen every part, inside limits a quality engineer signed off.
            
scrap 4-5% → 1-2%

        

        
C# · .NET · Keyence TM-X · Siemens 828D · OPC

The business side
How I decide what is worth building

    
I moved from engineering into product ownership and back to the field, so I read a P&L as readily as a stack trace. Every system above was justified in the customer's own unit before a line of code was written.

    

      
01
Start with the operator, not the ticket
The bottleneck is rarely the one named in the meeting. On one product it turned out to be hand-configured installs, not the software.

      
02
Agree the number before the work
Accept and stop thresholds are set up front. Two roadmap items were retired for missing theirs, with the reasoning written down.

      
03
Price AI by what it costs to run
Credits sized against measured cost to serve, the paywall placed after first value, and work priced per unit instead of per project.

      
04
Payback over novelty
Days per quote, scrap percentage, dollars per drawing. If a system cannot move a number the business already tracks, it does not get built.

Cybersecurity
Defence in depth, from the firewall to the agent

    
Connecting AI to an ERP and to machines that cut metal raises the stakes. Security is designed in at every layer, so one failure never reaches a system of record.

    

      
PERIMETER
One door in
Sophos XGS firewall, a single HTTPS entry point, direct IP and port access blocked. Administration only over WireGuard or Tailscale.

      
TRANSPORT
Encrypted everywhere
TLS on every app through nginx, with a wildcard certificate from an internal certificate authority and a documented renewal procedure.

      
IDENTITY
Single sign-on, short-lived tokens
SAML and OIDC for every app. Access is granted and revoked once, at the identity layer, instead of in each system.

      
DATA
Least privilege by default
Read-only database roles for dashboards, least-privilege IAM per cloud job, and writes only through narrow, audited endpoints.

      
AI
Agents on a short leash
Typed tools instead of raw SQL, local models so sensitive data stays on site, and one shared rate limiter and budget for every agent.

      
MACHINES
Software cannot overdrive hardware
Machine writes go through one control service with a deadband and a per-step clamp, so no single command can overdrive a tool. Remote access to cells is VPN only.

Decision record
Trade-offs I made, and what each one cost

    
Every design choice gives something up. These are the ones that shaped the system, with the price stated.

    

      
DecisionChoseGave upWhy it was right here

      
        
D-01Modernise the ERPWrap it in a read APIA clean data model; the legacy system stays a dependencyValue in weeks instead of a multi-year migration, with zero disruption to a system the business trusts. The API also becomes the seam for replacing it later.

        
D-02Where the pipeline runsSelf-hosted Git and webhooks on siteManaged CI convenience; I own the upkeepA plant network cannot depend on an outbound connection to ship a fix, and source and data stay inside the building.

        
D-03Which model does the workLocal first, premium only on evidencePeak accuracy on the first pass; a more complex pipelineCost falls by more than half and most data never leaves the site. The accuracy is recovered by escalating only the uncertain rows.

        
D-04How to trust AI outputDeterministic checks against physicsGenerality; each document type needs its own checksA model's own confidence score is not calibrated. Geometry and mass either agree with the drawing or they do not.

        
D-05How hard the controller correctsDeadband and a per-step clampSpeed; it takes several parts to return to nominalOne bad gauge reading can never scrap a part or crash a tool. Slow and bounded beats fast and occasionally wrong.

        
D-06Database availabilityAvailability groups tuned for zero data lossSome write latency and extra hardwareFor a system of record, losing a committed transaction costs far more than a few milliseconds per write. Failover was tested, not assumed.

        
D-07Rolling up quote costsOne recursive query over the parts graph, with cycle guardsSimplicity; recursive SQL is harder to read than a loop in application codeA nested bill of materials is a graph. Walking it in the database is one round trip instead of one query per part, and the cycle guard stops a bad parent link from looping forever.

        
D-08Remote desktopsBrowser access over one HTTPS portNative-client performanceNothing to install on any laptop, one port to secure and audit, and no desktop port ever exposed to the network.

        
D-09Many sites, one productOne release with per-site configurationQuick one-off customisation for a single plantForks diverge and every fix has to be made several times. Configuration keeps every site on the same tested build.
