OT · networking · security · field work

Cloud

  • AWS data platform: PySpark on EMR and Glue, orchestrated with Step Functions, RDS and S3 for high availability
  • App hosting on ECS and AppSync for client front ends, least-privilege IAM throughout
  • Hybrid by design: plant workloads on site, packaged so the same release runs on any cloud Kubernetes

  • Rust going forward for new services: protocol bridges, edge agents beside machines, low-footprint APIs
  • Memory safety without a garbage collector, which matters for long-running code on plant hardware

02 · System design

The reference architecture I deploy into a plant

Five layers, each one replaceable on its own. Select any component to see what it does, the design decision behind it, and what it talks to.

PRINCIPLE 01

Confidence from physics, not from the model

Extraction is scored by OCR agreement, geometry and mass-from-geometry against printed weight, never by what the model says about itself.

PRINCIPLE 02

Clamp anything that touches a machine

Deadbands ignore in-spec noise and per-step limits stop a bad reading from driving a tool. Automation walks to the answer, it does not jump.

PRINCIPLE 03

Escalate on evidence

Cheap and deterministic first, local model next, premium model last and capped. Every rung must justify the cost of the next one.

PRINCIPLE 04

One release, per-site config

Sites differ in configuration, not in code. Helm values and governed constants instead of forks, so every plant runs the same tested build.

PRINCIPLE 05

Read-only until proven otherwise

Dashboards and agents get read-only roles on systems of record. Writes go through narrow, audited endpoints with an owner.

PRINCIPLE 06

Leave it runnable

Runbooks, status pages and one-click paths, so the customer's own staff keep it going after I leave.
